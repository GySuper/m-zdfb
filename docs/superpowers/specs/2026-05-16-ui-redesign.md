# UI 重设计规范 · 九豆·自动发布平台

> 日期:2026-05-16
> 范围:整套 Web UI(`wxsp/templates/*` + `base.html` 全局样式)
> 不动:FastAPI 路由、模板上下文字段名、HTMX/SSE 通信协议
> 目标:友好、方便、舒适、简单。为未来"小红书/抖音"等多平台预留架构

---

## 1. 设计原则

1. **少即是多**:第一眼应该一眼看出"有没有事"、"要不要操作",而不是堆数字
2. **出错有出路**:每个异常状态旁边必须有"下一步该做什么"的明确入口(按钮/链接),不要只甩术语
3. **配置有人话**:每个配置项必须有一行人话描述"填什么、填错会怎样",不解释的字段就别放在 UI 上
4. **平台是顶层维度**:侧边栏顶部一个平台切换器;切换后整个工作区数据/导航都切换
5. **克制视觉**:白底 + 大量留白 + 单一主色;不堆色块、不用荧光、不用阴影炫技

## 4. 通用组件

### 4.1 卡片

```html
<div class="card">
  <div class="card-header">
    <h2>标题</h2>
    <div class="card-actions">右上角按钮</div>
  </div>
  <div class="card-body">...</div>
</div>
```

- 背景 `--color-surface`,边框 `1px solid --color-border`,圆角 `--radius-md`
- 内边距 `--space-4`(16px)
- 卡片之间间距 `--space-4`
- 不再用嵌套卡片(原 Dashboard 账号卡片是 card 套 card,看起来很闷)

### 4.2 按钮

```
.btn         默认(白底 + 灰边)
.btn-primary 主操作(石板蓝实色)
.btn-ghost   弱化操作(无边框,hover 才有底色)
.btn-danger  危险操作(红色,需 confirm)
.btn-sm      小尺寸(表格行内)
```

按钮高度:默认 32px,small 26px。

### 4.3 状态徽章 (badge)

```
.badge-ok       绿底绿字  (登录正常 / 已发布)
.badge-warn     黄底棕字  (即将过期 / 发布中 / 已中断 / 即将上线)
.badge-error    红底红字  (已过期 / 失败)
.badge-info     蓝底蓝字  (进行中 / 提示)
.badge-mute     灰底灰字  (待发布 / 已跳过 / 未知)
```

### 4.4 表格

- 表头 `--color-border-soft` 浅灰底,字号 13px,字重 500
- 行间分隔用 `--color-border-soft`(几乎看不见的横线),不再有重边框
- hover 整行变 `--color-primary-soft`
- 单元格内 padding `8px 12px`

### 4.5 健康状态条 (新组件)

Dashboard 顶部 sticky 横条,根据是否有异常显示两种状态:

**正常时**:

```
┌────────────────────────────────────────────────────────┐
│ ✓ 一切正常 · 今日 80 条任务全部按计划进行              │
└────────────────────────────────────────────────────────┘
背景 --color-ok-soft,左边 4px 实色边 --color-ok
```

**异常时**:

```
┌────────────────────────────────────────────────────────┐
│ ⚠ 3 项需要处理                                         │
│   · 美食号 Cookie 即将过期(剩 2 天)  [扫码续期 →]    │
│   · 任务 #142 失败(NAS 不可达)        [查看 / 重试 →] │
│   · 历史积压 12 条                          [处理 →]   │
└────────────────────────────────────────────────────────┘
背景 --color-warn-soft,左边 4px 实色边 --color-warn
```

每个异常项右侧都有**对应的操作按钮**,点击直达可操作页面。

**分组规则**(从用户场景出发,不是按代码模块):

|------|---------|------|

| 连接服务 | feishu + paths(NAS) | 飞书凭据 + NAS 路径,这是和外部世界的对接 |
| 调度时间 | scheduler.* | 启用定时 / 触发时间 / 分配策略 |
| 通知告警 | monitoring.* | Cookie 阈值 / 企微 / 告警事件类型 |
| 系统 | app + webui | 数据/日志目录 / 时区 / 端口 |
| (进阶) 字段映射 | feishu.field_map | 默认折叠,99% 用户不动 |
| (进阶) 高级 YAML | 整个 config.yaml | 用编辑器直接改 yaml,给开发者用 |

**字段必须配人话**:每个 input 下方一行 `--text-xs` 灰字,告诉用户:
- 填什么(例如"飞书开放平台获取的应用 ID")
- 填错会怎样(例如"填错会导致同步失败,具体错误见日志页")
- 何时需要改(例如"99% 用户不需要改这个,默认即可")

## 8. 不做的事(YAGNI)

- 不做 dark mode(运营白天用,本地工具,没必要)
- 不做移动端适配(本地工具,桌面浏览器为主)
- 不做国际化(中文唯一,代码里直接写中文)
- 不引入 CSS 框架(Tailwind/Bootstrap),纯手写 CSS 在 base.html 里(单文件好维护)
- 不引入图标库,需要时直接 inline SVG 或 unicode 符号(✓ ✕ ⚠ ◐ ⏱ ⏸ ▾ ▸ + 等)
- 不引入前端框架(Vue/React),坚持 Jinja2 + HTMX
